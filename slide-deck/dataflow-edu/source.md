# DataFlow-EDU 项目介绍源材料

## 项目定位

DataFlow-EDU 是一条面向教育学科语料库与评测 Benchmark 构建的端到端自动化生产管线。项目目标是把原始教材、课件或其他 PDF 教学资源，转化为高质量、结构化、可导出、可编辑的题库、训练语料与评测集。它强调“从一份教材到规模化题库”的生产能力，并把 DataFlow 的算子化清洗理念引入教育数据构建流程。

项目不是单点脚本，而是一个可拆解、可监控、可人工介入的半自动 Workflow。它覆盖文档解析、知识配置、题目生成、知识均衡、歧义清洗、领域对齐、去重、合成、翻译、执行与 LLM-as-a-Judge 评判等阶段。用户既可以从命令行按阶段运行，也可以通过教师友好的 WebUI 上传教材、配置参数、查看进度、编辑结果并导出 Word、PDF、JSON。

## 核心价值

教育领域构建高质量题库和 Benchmark 的难点在于：输入材料形式复杂，题目生成容易偏离教材，题型和知识点分布不均衡，清洗与评判成本高，最终产物还需要适配教师使用场景。DataFlow-EDU 的价值在于把这些环节串成可复用的工程化链路。

系统以教材等教学资源为输入，优先保证生成内容紧扣上传素材。它通过配置化的学科预设、核心素养体系、能力层级、题型和难度分布，把题库生成从“自由生成”约束为“面向教学目标的结构化生成”。随后通过多轮清洗与评判算子降低幻觉、重复、歧义和领域偏移。

## 总体架构

项目由三层构成：

- Python Core：`dataflow_edu/` 负责管线调度、算子执行、配置加载、LLM 客户端复用、评判与导出。
- DataFlow Operators：各阶段算子继承 DataFlow 的 `OperatorABC`，并注册到 `OPERATOR_REGISTRY`，形成可组合、可替换的处理单元。
- WebUI：`webui/` 提供教师端与管理员端。前端使用 Vue 3、Vite、Pinia；后端使用 Express、SQLite、SSE 和子进程调度 Python 流水线。

核心入口包括：

- `python -m dataflow_edu.edu_data_pipeline`：命令行交互式管线入口。
- `dataflow_edu/task_runner.py`：Web 任务运行器，负责按任务目录注入输入输出路径并写入进度。
- `webui/server/src/routes/tasks.ts`：上传、运行、SSE 进度、导出、任务管理等接口。
- `webui/frontend/src/views/teacher/`：面向教师的上传、配置、进度、统计编辑和导出界面。

## 管线阶段

DataFlow-EDU 的主流程可以概括为四个阶段：

1. 输入与配置：用户上传教材 PDF 或课件，选择学段、学科、知识方向、核心素养、题型、难度和运行参数。系统通过配置 schema、preset YAML 和 WebUI 向导把教师意图转为结构化配置。
2. 文档解析与生成：MinerU OCR 将 PDF 内容解析成 Markdown 或结构化文本，生成算子根据教材内容、学科 prompt 和题型要求产生题目。
3. 清洗、均衡与增强：知识均衡算子检查能力层级和题型分布缺口；歧义清洗与歧义修正减少表达问题；领域清洗与领域修正确保题目贴合学科；去重算子压缩重复样本；合成与翻译算子用于扩展数据形态。
4. 执行、评判与导出：执行算子和 judge 算子提供规则与 LLM 多维评判；最终题库可在线编辑，并导出 Word、PDF、JSON，包括教师版、学生空白版等。

## 技术特点

项目的第一个技术特点是算子化。新增能力不是散落在脚本里，而是作为独立 operator 接入 DataFlow 体系：包含注册、配置、CLI 入口、输入输出目录和统一运行协议。这让流水线具备可维护和可扩展的结构。

第二个特点是半自动。项目明确保留人工监控、管理和介入：命令行菜单让用户选择执行哪个步骤；WebUI 用 SSE 展示阶段进度和样例预览；编辑界面允许教师对题目进行增删改。它不把教育数据生产视为一次性黑盒生成，而是把 AI 生成与教师审核结合起来。

第三个特点是配置化与学科适配。项目维护初高中多学科 preset，覆盖语文、数学、英语、物理、化学、生物、政治、历史、地理等。不同学科可以加载不同 prompt 模板、核心素养体系、认知层级和默认难度分布。

第四个特点是面向真实部署。项目包含 Dockerfile、docker-compose、前后端分离部署、SQLite 用户与任务库、JWT、任务并发、超时、SSE watcher、导出去重、邀请码、审计日志、只读分享、下载安全和备份方案等 SaaS 化能力。

## WebUI 用户体验

WebUI 面向教师零编程使用。典型路径是：注册或登录账号，创建任务，上传教材 PDF 或 PPT，选择学科和参数，填写或使用平台 LLM key，启动流水线，观察实时进度，查看生成题目，在线编辑，最后导出教学可用的文档。

教师端重点页面包括：

- UploadView：上传 PDF/PPT、填写教材名、选择 LLM provider。
- ConfigView：向导式配置学科、核心素养、题型、难度和可选流水线步骤。
- ProgressView：实时显示 OCR、生成、清洗、评判等阶段进度，并预览最新题目。
- StatsView：合并统计与编辑，支持题目表格化修改、新增和删除。
- ExportView：选择阶段、格式、语言和版本导出。

管理员端保留看板能力，同时增加用户管理、邀请码、审计日志、平台 LLM 余额和配额观察。

## 示例输入与演示场景

项目 README 中使用高中生物必修一教材作为 Demo 场景。该场景体现了 DataFlow-EDU 的典型优势：教材内容经过 OCR 解析后，系统围绕课本知识生成选择题等结构化题目，再通过知识均衡、清洗、去重和评判保证题目覆盖、质量与可用性。虽然示例来自生物教材，系统设计目标是覆盖多学科、多学段和多类型教学资源。

## 当前成熟度与规划

项目已经从早期 CLI 与看板，演进为教师友好的 SaaS v1.0 形态。规划中包含后端账号与任务体系、教师端核心闭环、导出体系、核心素养配置、SaaS 上线、质量加固、教学物料和上线后功能扩展。

成熟度加固重点包括安全与稳定性：CORS 白名单、磁盘上传、PDF 文件头校验、强 JWT secret、密码强度、全局 rate limit、helmet、healthcheck、任务并发上限、任务超时、graceful shutdown、导出去重、DB 限流、prompt injection 防护、BYOK key 最小注入、审计日志、自动化测试、任务删除和邀请码机制。

后续产品演进包括：任务 ETA、批量管理、SQLite 自动备份、只读分享链接、文件夹分类、组卷模板、教师培训 deck、课件支持，以及可选择“从材料提取 QA”或“基于材料生成 QA”的双路径。

## 一句话总结

DataFlow-EDU 将教材解析、题库生成、数据清洗、质量评判和教师工作流串成可落地的教育数据生产基础设施。
